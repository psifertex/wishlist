A small, self-hosted family wishlist that runs on Cloudflare's free tier.

- **Anyone with the link can see a list and mark something as bought.** No account needed.
- **No spoilers.** Owners don't see what's been bought for them until the event date (or about two months later for lists without a date).
- **Add from any store.** A bookmarklet or iOS Share-sheet shortcut reads the price, pictures, selected size/color and book format from the page you're on. Amazon is supported first, and any page with an ISBN gets its cover from Open Library.
- **One login system you don't run.** Cloudflare Access handles Google/GitHub/email-code login; admins approve new people in the app.
- **A link per person.** Each person can have their own hostname that opens their next upcoming list.

See [docs/requirements.md](docs/requirements.md) for the full design.

## Development

Requires Node 22+ and pnpm.

```sh
pnpm install
pnpm db:migrate:local
pnpm dev            # builds the capture script, then runs wrangler dev on :8787
pnpm test           # Worker tests (in the Workers runtime) + capture script tests
pnpm typecheck
```

Locally you're logged in as `admin@example.com` (see `DEV_AUTH_EMAIL` in `wrangler.jsonc`), which becomes the first admin. Switch users with `/dev/login?email=someone@example.com`. Browsers resolve `*.localhost`, so a person hostname such as `kid.localhost:8787` works once an admin adds it.

## Layout

| Path | What |
|---|---|
| `src/` | The Worker: Hono routes rendered with JSX, D1 via Drizzle |
| `src/routes/public.tsx` | Public list pages and claiming |
| `src/routes/app.tsx` | Logged-in pages: lists, items, the add form |
| `src/routes/admin.tsx` | Approvals, people, hostnames, usage |
| `packages/capture/` | The capture script used by the bookmarklet and Shortcut |
| `migrations/` | D1 migrations generated by `pnpm db:generate` |
| `public/` | Static assets |

## Your family's config

Copy `config/family.example.jsonc` to `config/family.local.jsonc` (gitignored) and list your people, their login emails, admins, parents and hostnames. Then:

```sh
pnpm family            # writes routes + MAIN_HOST into wrangler.deploy.jsonc and builds the seed SQL
pnpm family --local    # also loads it into the local dev database (hostnames become <slug>.localhost)
pnpm family --remote   # also loads it into the deployed database
```

Re-running is safe. People added later in the admin pages are left alone.

## Deploying from GitHub

`.github/workflows/deploy.yml` tests every push and pull request, and deploys pushes to `main`: it applies D1 migrations, then runs `wrangler deploy`. Set these repository secrets (Settings → Secrets and variables → Actions):

| Secret | Value |
|---|---|
| `CLOUDFLARE_API_TOKEN` | API token with: Account: Workers Scripts Edit, D1 Edit, Account Settings Read; Zone (each gift domain): Workers Routes Edit, DNS Edit |
| `CLOUDFLARE_ACCOUNT_ID` | Your Cloudflare account ID |
| `WRANGLER_DEPLOY_JSONC` | Contents of your `wrangler.deploy.jsonc` |
| `FAMILY_CONFIG_JSONC` | Contents of your `config/family.local.jsonc` |

With the GitHub CLI:

```sh
gh secret set WRANGLER_DEPLOY_JSONC < wrangler.deploy.jsonc
gh secret set FAMILY_CONFIG_JSONC < config/family.local.jsonc
```

To load people, logins and hostnames from the family config into the database, run the workflow manually (Actions → Test and deploy → Run workflow) with **seed** checked. It's off for normal pushes so changes made in the admin pages aren't overwritten.
