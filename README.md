A small, self-hosted family wishlist that runs on Cloudflare's free tier.

- **Anyone with the link can see a list and mark something as bought.** No account needed.
- **No spoilers.** Owners don't see what's been bought for them until the event date (or about two months later for lists without a date).
- **Add from any store.** A bookmarklet or iOS Share-sheet shortcut reads the price, pictures, selected size/color and book format from the page you're on. Amazon is supported first, and any page with an ISBN gets its cover from Open Library.
- **One login system you don't run.** Cloudflare Access handles Google/GitHub/email-code login; admins approve new people in the app.
- **A link per person.** Each person can have their own hostname that opens their next upcoming list.

See [docs/requirements.md](docs/requirements.md) for the full design.

## Development

Requires Node 22+ and pnpm.

```sh
pnpm install
pnpm db:migrate:local
pnpm dev            # builds the capture script, then runs wrangler dev on :8787
pnpm test           # Worker tests (in the Workers runtime) + capture script tests
pnpm typecheck
```

Locally you're logged in as `admin@example.com` (see `DEV_AUTH_EMAIL` in `wrangler.jsonc`), which becomes the first admin. Switch users with `/dev/login?email=someone@example.com`. Browsers resolve `*.localhost`, so a person hostname such as `kid.localhost:8787` works once an admin adds it.

## Layout

| Path | What |
|---|---|
| `src/` | The Worker: Hono routes rendered with JSX, D1 via Drizzle |
| `src/routes/public.tsx` | Public list pages and claiming |
| `src/routes/app.tsx` | Logged-in pages: lists, items, the add form |
| `src/routes/admin.tsx` | Approvals, people, hostnames, usage |
| `packages/capture/` | The capture script used by the bookmarklet and Shortcut |
| `migrations/` | D1 migrations generated by `pnpm db:generate` |
| `public/` | Static assets |

## Your family's config

Copy `config/family.example.jsonc` to `config/family.local.jsonc` (gitignored) and list your people, their login emails, admins, parents and hostnames. Then:

```sh
pnpm family            # writes routes + MAIN_HOST into wrangler.deploy.jsonc and builds the seed SQL
pnpm family --local    # also loads it into the local dev database (hostnames become <slug>.localhost)
pnpm family --remote   # also loads it into the deployed database
```

Re-running is safe. People added later in the admin pages are left alone.

## Deploying from GitHub

`.github/workflows/deploy.yml` tests every push and pull request, and deploys pushes to `main`: it applies D1 migrations, then runs `wrangler deploy`. Set these repository secrets (Settings → Secrets and variables → Actions):

| Secret | Value |
|---|---|
| `CLOUDFLARE_API_TOKEN` | A Cloudflare API token; see [Creating the Cloudflare API token](#creating-the-cloudflare-api-token) |
| `CLOUDFLARE_ACCOUNT_ID` | Your Cloudflare account ID; see the same section |
| `WRANGLER_DEPLOY_JSONC` | Contents of your `wrangler.deploy.jsonc` |
| `FAMILY_CONFIG_JSONC` | Contents of your `config/family.local.jsonc` |

With the GitHub CLI (each command prompts for the value, or reads it from a file):

```sh
gh secret set CLOUDFLARE_API_TOKEN          # paste the token when asked
gh secret set CLOUDFLARE_ACCOUNT_ID         # paste the account ID when asked
gh secret set WRANGLER_DEPLOY_JSONC < wrangler.deploy.jsonc
gh secret set FAMILY_CONFIG_JSONC < config/family.local.jsonc
```

### One-time setup

Do this once, from your own machine, signed in with `pnpm exec wrangler login` (a browser sign-in, so no long-lived token with zone access is created):

1. Make sure every domain you'll use is a zone in your Cloudflare account, and that the hostnames you picked have no existing DNS records.
2. Enable R2 in the dashboard (R2 Object Storage → Enable). Cloudflare asks for a payment method; the app's caps keep it well inside the free tier.
3. Create the database and bucket, and put the database ID into `wrangler.deploy.jsonc`:

   ```sh
   pnpm exec wrangler d1 create wishlist
   pnpm exec wrangler r2 bucket create wishlist-images
   ```

4. Apply migrations, load your family config, and deploy once with routes, which attaches the custom domains:

   ```sh
   pnpm db:migrate:remote
   pnpm family --remote
   pnpm ship
   ```

Adding a hostname later works the same way: add it to the family config, then run `pnpm family && pnpm ship` locally, or attach it in the dashboard under the Worker's Settings → Domains & Routes.

### Creating the Cloudflare API token for GitHub Actions

CI deploys run `pnpm family --no-routes`, so they never change domains or DNS, and the token needs **no zone permissions at all**. Cloudflare tokens can't be limited to a single hostname, only to whole zones, so keeping zones out of the token entirely is the safer setup.

1. Open the [API Tokens page](https://dash.cloudflare.com/profile/api-tokens) and click **Create Token** → **Create Custom Token**.
2. Name it, e.g. `wishlist deploy`.
3. Add exactly these permissions:

   | Type | Permission | Access | Why |
   |---|---|---|---|
   | Account | Workers Scripts | Edit | Upload the Worker |
   | Account | D1 | Edit | Apply migrations (and the optional seed run) |
   | Account | Account Settings | Read | Wrangler reads account details |
   | User | User Details | Read | Wrangler checks who the token belongs to |
   | User | Memberships | Read | Wrangler lists the accounts the token can use |

   Not needed in CI: any Zone permission, Workers R2 Storage, Workers KV Storage, Workers Tail, Cloudflare Pages.

4. **Account Resources:** Include → your account. There are no zone resources.
5. Leave **Client IP Address Filtering** empty (GitHub Actions has no fixed IP addresses). Optionally set a TTL and a reminder to rotate it.
6. **Create Token**, copy it, then test it. The result should include `"status": "active"`:

   ```sh
   curl -s https://api.cloudflare.com/client/v4/user/tokens/verify -H "Authorization: Bearer <token>"
   ```

7. **Account ID:** shown in the right sidebar of **Workers & Pages**, or `pnpm exec wrangler whoami`.

If a deploy fails with an authentication error (code 10000), the error names the API call that was refused; add the matching permission and rerun.

To load people, logins and hostnames from the family config into the database, run the workflow manually (Actions → Test and deploy → Run workflow) with **seed** checked. It's off for normal pushes so changes made in the admin pages aren't overwritten.
